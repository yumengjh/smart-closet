# 实时试穿测试版

实验分支：`codex/realtime-tryon-poc`。配对 worktree：`/Users/yaopinxin/project/tryon-lab-20261014`。

## 使用

当前预览为 http://localhost:18084/try-on ，接口直接代理到原 8080 服务，使用原衣柜与原账号。localhost 可以沿用浏览器中原来的 localhost:8080 登录；127.0.0.1 的 Cookie 独立，不能沿用。此前独立测试账号及单件衣物数据库已停用。

1. 选择衣柜中的普通上衣。页面显示实际纹理；缺少干净素材时导入透明上衣 PNG。
2. 点击“开启摄像头试穿”，允许摄像头。双肩清楚入镜即可开始，先正面站立，再小幅抬手。腰部不在画面中时显示“半身追踪中 · 衣长为估计”；腰部入镜时衣长更稳定。
3. 切换“随动作变形 / 刚性贴图对照”，观察袖子差异。宽度、长度、上下位置只影响当前预览。
4. “用本地短视频测试”可重复观察动作；视频不上传。“保存当前画面”下载当前镜像状态的 PNG。
5. 点击“停止试穿”释放摄像头和姿态 Worker；离开页面或切到后台也会停止。
6. MacBook 预览跟随相机实际比例，右下角“全屏预览”可放大；全屏内可停止试穿或退出。画面底部显示实际采集尺寸。

摄像头需 HTTPS 或 localhost。HTTP 局域网地址可看页面，但不能据此保证手机摄像头可用。

## 构建

```bash
npm ci
npm run setup:try-on
npm run build:server
npm run preview:try-on
```

模型由显式设置脚本安装，不在服务运行时下载；摄像头帧不发送云端。WASM、模型和浏览器 QA 资料保持本地，不入 Git。
`preview:try-on` 只启动前端并代理现有 API，不再启动第二个后端或打开原 H2 数据库。原服务须已在 8080 运行；可用 CLOSET_API_PROXY_TARGET 指定现有服务。

## 验证及边界

- 95 项测试、vue-tsc 与生产构建通过。前端源码经 build:server 发布到配对实验后端，并从 dist 启动当前前端预览。
- 本地独立账号和数据目录完成真实 API 登录、衣柜读取、透明 INPUT 纹理选择，以及 Chromium 中的 Pose Lite GPU、视频输入与 WebGL 合成。
- 390px 视口检查：文档宽度 390px，无横向溢出。只验证布局，没有验证真实手机算力和摄像头。
- 10 张混合上衣原抠图，8 张通过轮廓模板、2 张拒绝；不代表 8 张视觉效果合格，也不是标准 T 恤成功率。
- 本机约 10 分钟运行后的单次读数：显示 30 FPS、姿态 10 FPS、滚动推理 p95 18 ms，取帧/传递/推理 12 ms；不是端到端动作延迟或手机性能承诺。
- 观察到衣物随人移动，原衣物肩部仍露出，袖子和前臂遮挡近似明显。当前可以比较颜色、比例与跟随能力，尚不能自然替换所有衣物。
- 首次浏览器验证发现 1.1 运行时的 module WASM 加载兼容问题，以及强制 loseContext 后无法重新启动的问题，均已修复并再次实跑。

## 漏识别修正（2026-10-15）

原实现要求双肩、双髋都高置信，任一帧不合格即隐藏；超过 500ms 的结果也被隐藏。裁腰测试中模型已找到人，旧规则仍 0/8 接受。修正后相同采样 8/8 进入半身追踪；未降低模型检测阈值，改进的是应用接受规则、短暂丢点与过期处理。

双肩置信度 .4 起追、.3 保持；缺髋或髋在画面外时采用上衣模板估计衣长。丢点保留不超过 700ms，结果处理超过 1200ms 不再接收。状态区分别提示寻找人物、肩膀不清楚、半身、短暂丢失和设备慢。

连续录制测试首次采样：全身 13/13、半身 36/37 可见；250ms 短暂空画面 4/4 保留；离开后稳定空画面 0/6 可见；重新入镜 13/13 可见。半身仍出现一次检测器重新定位中断，真实摄像头和手机还需实测。截图 `output/playwright/try-on-half-body-fix.png`。

## 原衣柜与透明素材修正（2026-10-15）

用户指出素材错误，核对后确认：AI_ENHANCED 同时标记加白边前的透明整理图（GENERATE）和加白边后的展示贴纸（STICKER）。旧版全部排除 AI_ENHANCED 并优先 BASE，导致错用原始褶皱、甚至带人物残留的基础抠图。黑色短袖、灰色短袖、白色水手服的 step-2.png 均已规整且有透明 Alpha，不需要重新抠图或生图。

现在读取衣物现有工作流，剔除 STICKER 步骤产物与失败/拒绝素材，优先使用当前展示图同一流程中的无白边透明整理图，再回退基础图。重复读取有本页缓存，切衣异步结果仍受选择版本保护；不写衣柜、不产生新任务或模型调用。

实际用户 Chrome 中沿用原账号读到 53 件上衣，默认 T 恤、切换白色短袖均显示“衣柜 AI 整理图 · 无白边透明版”。截图 `output/playwright/real-wardrobe-connected.png`。另用原数据三张 step-2.png 在独立浏览器 QA 页运行真实 Pose + WebGL，每件约 3 秒，无渲染错误；已目视确认无原图人物残留或装饰白边，但抬手袖子扭曲和遮挡仍明显。此 QA 页通过本机路由读取原文件，不假称已在用户摄像头中验证。

Chrome 扩展未开本地文件访问，不能通过扩展向真实账号页面代选测试视频；没有为此更改权限。视频合成使用独立 Playwright QA 浏览器完成。

## MacBook 画面比例修正（2026-10-15）

旧版向所有摄像头请求 640×960，导致笔记本摄像头偏向竖屏裁切；CSS 放大无法恢复采集阶段丢掉的视野。改为仅建议宽 1280 / 30 FPS，不指定高度或宽高比；浏览器支持 resizeMode 时要求 none，使用原生采集模式（[W3C 说明](https://w3c.github.io/mediacapture-main/#dom-videoresizemodeenum-none)）。

画布按 videoWidth/videoHeight 更新布局，以 contain 完整展示；桌面页宽增加、控制栏略收窄，支持原生全屏与退出，竖屏输入仍按原比例显示。全屏只改变展示面积，原视频、检测点、网格、保存画面使用同一组坐标。

类型检查与 build:server 通过。已在用户 Chrome 的 MacBook 实际摄像头运行：video 为 1280×720，渲染缓冲为 960×540，GPU Pose 正常；全屏、全屏停止和退出可用。测试仅读取尺寸和文字状态，没有截取或保存实时人物画面。停止后 video 暂停、src 清除、尺寸为 0。停用画面截图 `output/playwright/try-on-wide-canvas.png`。没有据此声称手机或衣服贴合已验收。

本地截图：`output/playwright/try-on-running-top.png`、`try-on-mobile.png`；素材和录制视频在 `.local/try-on-fixtures/`。视频为 TensorFlow 官方测试样本，地址：https://raw.githubusercontent.com/tensorflow/tfjs-models/master/pose-detection/test_data/pose_squats.mp4 。样本仅用于本地测试，不随产品分发。
