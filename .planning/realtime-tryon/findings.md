# 当前实现与决策

- 后端 QuickIntakeService 保留 base-cutout.png（BASE），展示图 BASE_STICKER 含白边。
- Garment.images 含素材 ID、kind 和 URL，现有授权文件接口可读取干净 BASE，不必为实验新增后台路由或数据迁移。
- 现有动作卡为远程单图识别、14 个示意关节，与实时摄像头追踪独立。
- 实验先支持单件普通上衣；采用 Alpha 轮廓估计锚点、三角形纹理映射和分区约束。
- 摄像头视频只在浏览器内处理，不上传；本地导入短视频作为可重复的测试输入。
- 原穿衣物露边、遮挡近似与转身受限需要显式说明；不能用模拟骨架证明真实 Pose 效果。
- 技术资料：https://ai.google.dev/edge/mediapipe/solutions/vision/pose_landmarker/web_js 。detectForVideo 同步，推理放 Worker，保留最新帧而不排队。

2026-10-15 漏识别反馈：旧版要求肩/髋四点全部 visibility >= .55，任意一帧不合格即清空，并按采集时间 500ms 隐藏。真实 Pose Lite Worker 在裁至原视频顶部 40% 的 8 个采样中均检测到双肩，但髋部置信度 .13–.22，旧规则 0/8 接受。新逻辑保持模型本身 .5 阈值，改用双肩 .4 起追、.3 保持；缺髋时使用像素空间的上衣模板衣长，明确标记为估计。丢点最多保留 700ms，有效结果最多允许 1200ms 处理耗时，停止/重开重置状态。

连续视频首次检查：全身 13/13 显示、半身 36/37 显示、250ms 短暂空画面 4/4 保留、离开后稳定空画面 0/6 显示、重新入镜 13/13 显示。半身仍有一次检测器重新定位造成的中断；不能据此声称真实摄像头已完全解决。

原素材反馈：不应将 AI_ENHANCED 整类排除。QuickIntake 的 GENERATE 和 STICKER 都使用该 kind，原来的 step-2.png 已透明、规整；BASE 反而保留旧褶皱/人物残留。三件原数据目视比较确认。候选必须按现有工作流步骤判断，优先当前展示图同流程的干净整理图。用户要求原衣柜，预览须代理原 8080 的授权接口，不能继续用独立账号的一件测试图代表实际数据。

MacBook 画布问题根源在采集约束 640×960，原渲染器本身已画完整纹理。现不限定高度/宽高比，支持时要求 resizeMode=none；只有更改 CSS 无法恢复旧采集被裁去的区域。实际摄像头已读到 1280×720，WebGL 960×540 保持同一比例。画布按源比例布局，提供全屏；不对用户实时人物画面截图。
