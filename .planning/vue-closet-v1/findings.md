# 实施发现

- `smart-closet` 起初是空目录。
- 服务端是 Java 21、Spring Boot 4.1.1、H2/Flyway；无 Spring Security，也无用户归属列。
- 现有衣物与工作流接口已实现图像处理和元信息编辑；衣物列表裸数组，缺分页总数、搜索、筛选、删除、确认、额度。
- 所有原图与派生图片由 API 返回，需要加入同一归属鉴权。
- 独立分割和贴纸数据是文件，不在现有关系表；要有持久化所有者索引。
- 现有仓库有大量未提交文件；必须保护用户改动。
- Node 24.18.0、npm 11.16.0 可用。
- 新增登录会话后业务 API 统一校验已登录和完成首次改密；受邀用户的 AI 模型受服务端默认许可约束。
- Vite 原型可代理本地后端，`npm run build:server` 会以真实 API 模式发布到 Spring Boot 静态目录；Vue history 路由由 SPA forward 映射支持。
- 幂等键命中已有任务前必须先验证该任务的 owner；跨账号任务、图片和衣物请求按 404 隐藏对象存在性。
